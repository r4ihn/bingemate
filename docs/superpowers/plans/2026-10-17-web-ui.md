# BingeMate Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build every WH-owned page of `apps/web` (TASKS.md §4 UI, §7 UI, §8) against typed mock data, so each page works today and goes live by switching one API module.

**Architecture:** Shared UI primitives (Tailwind, tokens from `docs/ui.md` B2) → one API module per resource that returns typed data from an in-memory mock store unless `VITE_USE_MOCKS=false` → pages built only from primitives and API modules. UI-only types live in `apps/web/src/types/`, not `packages/shared`, until endpoint owners agree on shapes.

**Tech Stack:** React 18, React Router 7, Tailwind 4 (already installed), Vite 8, Vitest 5 (+ jsdom and Testing Library, Task 0).

**Spec:** `docs/ui.md` (Part B is our design; Part A is the reference). Task list: `TASKS.md`.

## Global Constraints

- Dark theme only; font Inter; tokens exactly as `docs/ui.md` B2 (already in `src/styles/global.css` `@theme`).
- Pill radius `999px`, poster radius `8px`, panel radius `16px`; spacing steps 4, 8, 12, 16, 24, 32, 48, 64 px.
- One accent: `--accent` `#f5c518`; text on accent is `--accent-ink` `#111111`, never white.
- Every interactive element keeps the yellow focus ring; poster colour-on-hover must also work on keyboard focus.
- Honour `prefers-reduced-motion`; ghost words are `aria-hidden="true"`.
- No IMDb name/logo and no Dune artwork; mock posters are gradients, mock titles are fictional.
- No new dependency except Task 0's test tooling (needs WH approval and a STATE.md justification).
- Do not build Browse filters or trending queries (SJ, TASKS.md §8). Do not edit `packages/shared` or `TASKS.md` in these tasks.
- Backend still enforces permissions; UI gating is UX only.

## Review Focus

1. A 401 mid-session on a public page (e.g. posting a review) must not leave a dead form: expect an error message with a login link.
2. Rating input given 0, 11, empty or non-numeric: expect an inline error and no submit.
3. Editing an `APPROVED` title: expect the re-submit warning and no save until confirmed.
4. Zero results (no reviews, empty list tab, empty queue) and missing poster: expect an empty state, never a blank area.
5. Double click on submit/approve/delete: expect one request only.
